# ADR-0001：整体架构采用「Mac 上的本地服务 + 网页界面」

日期：2026-10-06　状态：**已被替代**（2026-10-06，见文末「替代说明」）

## 背景

- 用户要求 Mac 和手机都能用。
- 「背 · whisper 比对」依赖本机的 mlx_whisper，它只能在 Apple 芯片的 Mac 上运行，手机上跑不了。
- 「贴 B 站链接下载」依赖 yt-dlp，同样只能跑在电脑上。

## 决定（原方案，已不采用）

在 Mac 上运行一个本地服务，负责三件事：提供网页界面、调用 whisper 转写录音、调用 yt-dlp 下载音频。Mac 和手机都用浏览器打开同一个网页。练习记录也存在 Mac 上，两边看到的是同一份。

不做原生 App，因为第一版的目标是尽快每天用起来；网页一份代码就能覆盖两种设备。

## 待定：手机怎么连到 Mac（原方案，已不采用）

手机网页要调用麦克风，浏览器要求页面走 HTTPS。三个候选：

1. **只用「录音后上传文件」**：手机网页用系统自带的录音或选择文件方式，可能不需要 HTTPS。不改任何网络配置，但体验差一些，能否在 iPhone Safari 上用需要 Spike 验证。
2. **本地自签证书（mkcert）**：在 iPhone 上安装并信任一个证书，只在家里局域网能用。不改网络配置。
3. **Tailscale**：手机和 Mac 组成私有网络，自带 HTTPS，出门也能用。**属于网络配置，必须用户明确同意。**

计划：先用方案 1 做 Spike S2；不行再请用户在 2 和 3 之间选择。

## 后果（原方案）

- Mac 关机或休眠时，手机端无法转写；自评、诵读这类不依赖 whisper 的功能，应设计成离线也能用。
- 出门在外能否使用，取决于手机连接方案的最终选择。

## 替代说明（2026-10-06）

用户的最新澄清和原方案的前提冲突，原方案不再采用：

- 手机要通过线上网页随时使用，每天练习不能依赖 Mac 开机。原方案把 Mac 当作每天练习的服务端，Mac 一休眠，手机就用不了。
- Whisper 只是后置的可选附加功能，不再是核心，所以「手机录音交给 Mac 转写」不再需要，Spike S1、S2 一并取消。
- 下载和转写只发生在准备材料阶段，可以在 Agent 会话里用 Mac 完成，不进入每天的练习流程。

**推荐的新方案**（详见 PRD v0.2 第八节）：用 GitHub Pages 托管静态前端，进度同步用 Cloudflare Worker 加 D1 数据库；练习事件只追加不覆盖；Agent 只读访问进度；Mac 只在准备阶段使用。第一版不使用 GitHub Releases。

**仍待定**：

1. 音频和受保护材料的存储位置与鉴权方式。私人课程和有版权的音频默认受保护；用户确认可公开分享的材料，按实际权限处理。
2. 前端最终放 GitHub Pages 还是其他静态托管。
3. 在连续音频上做 A-B 循环的精度，以及经鉴权代理读取时对 HTTP Range 的支持，需要实测（PRD 的 T1），再决定要不要预切音频。

以上待定项确定后，再写新的 ADR 记录正式决定。
